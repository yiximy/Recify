## 3. 统计口径（`store.get_tag_stats()`，务必与导出共用同一份）

对每个标签 T：
- **票据集合** = {发票 f : f 带 T} ∪ {发票 f : f 属于带 T 的组合}
- **张数** = 票据集合大小（发票张数）
- **支付集合** = 票据集合中每张发票的 `linked_payment_ids` **并集去重**（跳过不存在/missing 的支付记录）
- **金额** = Σ 支付记录的 `amount.final_amount`（None 视为 0）
- **日期区间** = 票据集合的日期（`store.get_document_date(f)`，回退文件修改时间）的 [min, max]
- **备注** = 组合名（若该类别来自组合，多个用、连接）＋「含 N 张未匹配支付」（N>0 时；N = 票据集合中无有效支付记录的发票数）
- **未分类**（虚拟类别，仅当导出对话框勾选时出现）= 发票自身无标签**且**其所属组合也无标签的那些发票，同上口径
- 跨类别提示：同一支付记录若被两个类别共同引用，会在两个类别各计一次（**类别内已去重**）；
  这点写进 README，不额外处理

日期区间显示格式（对齐模板）：同年 → `2026.6.30-7.21`；跨年 → `2026.12.30-2027.1.5`；同一天 → `2026.6.30`

# 追加（第 2 轮，人类 2026-09-30 拍板）：支付侧标签参与统计

第 1 轮实现严格按第 3 节口径，导致「给支付记录/支付组合打的标签不参与统计」（Codex 已提异议）。
人类拍板：**支付标签只影响金额，不影响张数**。请按下述修正 `app/core/tag_stats.py`（唯一统计实现）：

1. **类别 T 的支付集合** = 三者并集去重（跳过不存在/missing 的支付记录）：
   - 发票集合（= 发票自身带 T ∪ 属于带 T 的**发票**组合）的 `linked_payment_ids` 并集
   - 支付记录自身带 T
   - 属于带 T 的**支付**组合的支付记录
2. **金额** = Σ 上述支付集合的 `final_amount`（支付记录的 `final_amount` 优先 `edited`）
3. **张数 = 发票集合大小（不变）**：支付标签**不得**让发票进入票据集合；
   纯支付类别（只给支付打了标签、无关联发票）→ **张数 0，金额 > 0**（这是预期行为）
4. **「未分类」判定收紧**（避免同一笔钱被两个类别各算一次）：
   发票计入未分类需同时满足：自身无标签、其发票组合无标签、**其关联支付记录无标签、其关联支付所属支付组合无标签**
5. **备注**：`含 N 张未匹配支付` 口径不变（N = 类别内无有效支付记录的发票数）；组合名合并列表
   **同时纳入支付组合名**（若有支付组合贡献了金额）
6. **明细工作表**：原「标签」列拆成 **「发票标签」「支付标签」两列**（分别取发票侧/支付侧有效标签，
   各行按当前明细行对应的发票/支付取），便于核对
