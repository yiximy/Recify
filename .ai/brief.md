# 任务简报：组合定位/组合重命名/按钮布局（比对关联模式）

人类 2026-09-28 真机反馈三项。

## 1. 组合右键「定位所有」另一侧为空（Bug，根因已由 Claude 定位）

**根因**：`app/ui/widgets/file_list_panel.py:513` 的 `_combo_partner_ids` 把
`_partner_entries()` 的 `(文件名, file_id)` **解包反了**：

```python
for pid, _ in self._partner_entries(f):   # ✗ pid 实际是「文件名」
```

同文件其它调用点（:461 / :831 / :936 / :963）都是正确的 `for _, pid in ...`，**只有这一处反了**。
后果：组合菜单「定位所有」把**文件名**当 file_id 传给另一侧 `set_located_files()` → 全部不匹配 → 另一侧空白。
（子文件右键走 `:831` 正确路径，所以子文件能正常定位——与人类观察一致；「取消所有关联」用 `:963` 自己遍历，因此不受影响。）

**修复**：改为 `for _, pid in ...`。**要求**：顺手核对 `_combo_partner_ids` 的全部调用点（`_show_combo_menu` 的两条分支），确保组合「定位所有」与「取消所有关联」判空逻辑都拿到 **file_id 列表**；并检查是否还有别的 `(name, id)` 解包写反处（grep `_partner_entries`）。

**验证**：发票组合（2 成员）↔ 2 张支付各有关联 → 组合右键定位所有 → 另一侧应显示**支付组合/对应支付行**（可见且展开）；支付侧组合反向同理。

## 2. 组合重命名（新能力）

现状：`_update_link_buttons` 仅在「单文件 ↔ 单文件」且 `is_linked` 时启用「重命名关联」；
选中组合时按钮置灰。人类要求：**选中组合 + 其关联侧**时按钮可用，输入新名后**组合与关联文件统一改名**。

### 交互
- 「重命名关联」启用条件：两侧都有选中（文件或组合）**且两组之间存在 ≥1 条关联**
  （单文件↔单文件的原有 `is_linked` 语义是该条件在 1×1 下的特例，保留即可）。
- 对话框默认名：选中单文件 → 该文件名去扩展名（现状）；选中组合 → **组合名**。

### 重命名语义（层：Store）
新增 `Store.rename_group(invoice_ids, payment_ids, new_base, combo_ids=()) -> list[str] | None`：
- 目标名：组内文件按 **(所在目录, 扩展名)** 分组编号——第 1 个 `<新名>.<ext>`，
  之后 `<新名>_2.<ext>`、`<新名>_3.<ext>`…（同目录同扩展名必须唯一；跨目录/跨扩展名互不影响）
- **冲突即失败**（不做自动跳号，保持现有「目标已存在 → 失败」语义）：任一目标路径已存在于磁盘
  且不属于本组文件自身路径 → 返回 `None`
- **先算全部目标名，再执行重命名**；任一 `os.rename` 失败 → **回滚已改的文件**并返回 `None`
  （顺带修掉 backlog 里「双文件重命名非原子」的 P2：失败不再留下磁盘/Store 不一致）
- 交叉引用重映射：`linked_*_ids`、`associations`、**`combos[*].file_ids`**（沿用现有 old→new 重映射逻辑，
  建议抽成私有 `_remap_file_ids(old_to_new)` 供两处复用）
- **组合名同步**：`combo_ids` 内的组合 `name` 改为 `new_base`
- 最后统一 `_save()` + `_notify()`（**只写一次盘**，不要每个文件写一次）

`rename_linked_files(inv_id, pay_id, new_base)` 改为薄封装（转调 `rename_group([inv],[pay],new_base)`），
保持返回值与失败语义不变（现有单文件调用方零改动）。

### UI 层（compare_page）
- `_on_rename`：两侧收集 ids（组合 → `combo["file_ids"]`，文件 → 自身），组合 id 一并传入；
  成功提示：单文件↔单文件保持原文案；组合场景给「已统一重命名 N 个文件：<前 3 个新名>…（组合名同步为 X）」
- 现有「重命名成功后保持列表位置 + 顺延一行 + 清定位过滤」行为必须保留
