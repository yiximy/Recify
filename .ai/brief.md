# 任务简报：票面日期识别改为「PDF 文本层优先」（修 OCR 数字误读）

## 人类报告（2026-09-30）
导出的费用报销表里出现 `2026.8.2`，但发票文件夹里没有这个日期。

## Claude 已定位的根因（请复核，勿另起炉灶）

**发票 PDF 自带文本层，且字符是精确的；当前却用 OCR 文本来解析日期 → OCR 把数字读错就写错库。**

证据（真实数据，`D:/Download/安徽出差发票与支付记录/`）：

| 文件 | PDF 文本层（精确） | PaddleOCR 读到的 | 库中原值 |
|---|---|---|---|
| `【添猫出行-9.86元-1个行程】高德打车电子发票.pdf` | `开票日期：2026年08月26日` | `开票日期：2026年08月2日`（**漏读 6**） | `2026-08-02`（ocr）→ 导出显示 8.2 |
| `江苏高速通行费电子票据_20260917.pdf` | 标签行的值被拆成独立文字块（`2026`/`年`/`09`/`月`/`17`/`日`），**按行解析会漏** | `开票日期：2026年09月17日`（正确） | `2026-09-17`（ocr） |

即：**两个来源各有盲区**——OCR 会读错字符；而「按整行取文本」在标签与值被拆成多个文字块时会漏，进而回退到
第一个出现的日期（如「出口时间」），得出错误日期。

## 修复方案（已用真实数据验证有效）

### 1. 新增 `app/core/pdf_date.py`（Qt-free，使用 PyMuPDF `fitz`）
坐标法取「开票日期」标签**同一视觉行右侧**的值——两种版面都能命中：

```python
def labeled_invoice_date(path: str) -> str:
    """返回 YYYY-MM-DD；文本层无「开票日期」标签或无法解析时返回 ""。"""
```
实现要点：
- `page.get_text("words")` 取词及其 bbox；找匹配 `开\s*票\s*日\s*期` 的词
- 取「`x0 >= 标签.x1 - 2` 且与标签纵向有重叠（±3pt）」的词，**按 x 排序后无分隔拼接**
- 用 `date_parser` 既有正则解析拼接结果，并用其 `_to_iso_date` 做**真实日历校验**（复用，勿重写）
- 多页取第一个命中；`文档无文本层`（纯图片 PDF）→ 返回 `""`

已验证：真实数据 57 张有文本层的发票**全部命中**，且与当前（人工修正后）库值 100% 一致。

### 2. 识别优先级改为「文本层优先」
`app/ui/pages/amount_page.py::_persist_ocr_document_date` 改为：
1. `labeled_invoice_date(路径)` 命中 → 用它（**精确字符，不受 OCR 误读影响**）
2. 否则退回现有 `parse_date_from_lines(OCR 文本)`（纯图片 PDF / 无标签版面）
3. 都没有 → 保持现状不写
- **必须保留** `document_date_source == "manual"` 的跳过逻辑（手动优先，不得覆盖）

### 3. 新增「重算票面日期」入口（修复存量数据，避免重跑 OCR）
- 位置：计算金额模式工具栏（与现有按钮同排），按钮文案「重算票面日期」，带 tooltip 说明
- 行为：遍历**发票**（`store.get_invoices()`）
  - `document_date_source == "manual"` → **跳过**（不动用户手动设的）
  - 调 `labeled_invoice_date`；命中且与当前值不同 → `set_document_date(..., "ocr")` 更新
  - 未命中（纯图片 PDF）→ 跳过
  - 支付记录（图片）不处理（无文本层；仍需 OCR 或手动）
- 完成后提示：`已重算 N 张（更新 M 张，跳过 K 张手动）`；仅一次 `_save()`（批量）
- 逻辑放 core（`pdf_date.py` 或 store 薄方法），UI 只做按钮与提示

### 4. 顺带记录（不改，写进 backlog）
用户库中存在 **10 条「同路径重复记录」**（`missing=True` 的旧版本，因文件 mtime 变化而生成新 file_id；
137 条记录 / 127 个唯一路径）。不影响导出（缺失记录已被统计排除），但属同类「记录漂移」问题，记 backlog。
